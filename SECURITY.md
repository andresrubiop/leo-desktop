# Security boundaries

LEO is experimental software that can interact with a desktop. Start with optional capabilities disabled and authorize only the folders and actions you need.

- Inference is restricted to local Ollama. Optional account-usage and mail services are separate network integrations, not inference providers.
- The broker validates typed arguments, capabilities and one-use approvals. It does not execute shell text generated by an LLM.
- Screen, microphone, files, accessibility and attentive-mode capabilities have explicit controls. Attentive mode is opt-in.
- File mutations use an undo journal where supported. Undo is not a backup.
- Credentials belong in the operating system's secret storage. Do not put tokens, mail, runtime configuration or real screenshots in issues, commits or test fixtures.
- Third-party content may contain prompt injection. Treat it as untrusted input and keep approval checks in place.

Unit tests exercise policy behavior with synthetic data. They do not constitute a security certification or prove every integration safe. To report an issue that contains sensitive information, use the contact route on [andresrubiop.com](https://www.andresrubiop.com) rather than a public issue.
